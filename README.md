# iman

`iman` — менеджер сеанса IGUI и RetroArch для Linux. Он запускает меню,
принимает запрос на игру через локальный IPC, завершает GUI и запускает
эмулятор; после игры возвращает меню. Одновременно работает только один
дочерний процесс. В DRM-режиме менеджер удерживает дисплей между запусками.

Протокол, транспорт и общие примитивы дисплея/ввода предоставляет
[imanlib](https://github.com/idleboxed/imanlib).
Менеджер не устанавливает прошивку, не монтирует SD и не заменяет RetroArch
или ядра libretro.

## Требования и сборка

Нужны Linux, Rust 1.85 или новее, Cargo, procfs и доступный для записи tmpfs.
Для `pc` также нужны X11 и C-компилятор; для `drm` — доступный DRM/KMS.
Работа на конкретной плате зависит от ABI, драйверов и подготовленного комплекта.

Единственная зависимость от наших библиотек — `imanlib`.
Cargo получает её из Git-репозитория; точный коммит закреплён в
[`Cargo.toml`](Cargo.toml) и [`Cargo.lock`](Cargo.lock).
Соседние проекты и Git-подмодули для сборки iman не нужны.
При первой сборке требуется доступ к GitHub и реестру зависимостей;
после их загрузки Cargo поддерживает офлайн-сборку.

Из каталога `iman` соберите вариант с окном менеджера на ПК:

```sh
cargo build --locked --release --features pc
```

Результат — `target/release/iman`. Эта команда не собирает отдельный исполняемый
файл IGUI, RetroArch, ядра или игровой каталог. Их нужно подготовить отдельно.
Для DRM используйте feature `drm`; диагностика подключается дополнительно.
[Пример ARM-сборки](docs/runtime.md#сборка-для-rk3032).

## Быстрый запуск

Поместите программы и ресурсы в подготовленный комплект:

```text
ROOT/
├── system/
│   ├── iman/{iman,iman.json,emulation.json}
│   ├── igui/{igui,locales/,controls/}
│   └── retroarch/{retroarch,cores/,padconf/}
└── games/{catalogue.json,images/,thumbs/,states/,saves/}
```

IGUI нужны собственные ресурсы и профили контроллеров. Для запуска игр нужны
RetroArch, совместимые ядра, ROM и существующие каталоги `states/` и `saves/`.
Сеанс только с GUI может работать без `emulation.json`.

Минимальный `system/iman/iman.json` для ПК с X11:

```json
{
  "runtime_dir": "/dev/shm",
  "gui": {
    "display": {"backend": "desktop"}
  }
}
```

Запустите установленный менеджер:

```sh
/путь/к/ROOT/system/iman/iman
```

Корень определяется из расположения `system/iman/iman`, профиль загружается
автоматически. Для бинарника в другом месте укажите `--root`; отдельный профиль
выбирается через `--config`. Аргументы после `--` передаются IGUI, отключают
автозагрузку профиля и не сочетаются с явным `--config`.

Выбор игры в IGUI передаёт управление эмулятору; выход из игры возвращает меню,
закрытие меню завершает сеанс. Справка и запрос к уже работающему сеансу:

```sh
/путь/к/ROOT/system/iman/iman --help
/путь/к/ROOT/system/iman/iman ctl /путь/к/control.sock core.capabilities
```

Используйте сокет нужного сеанса: его путь записывается в RAM-журнал.
[Запуск и IPC](docs/runtime.md), [форматы конфигурации](docs/configuration.md).

## Features

- `rgb565` — включена по умолчанию; DRM-буферы RGB565 вместо XRGB8888.
- `pc` — собственное окно менеджера на X11.
- `drm` — владение дисплеем через DRM/KMS.
- `diagnostics` — все пассивные сборщики и интерактивный тест контроллеров.
- `io-monitor` — наблюдение за записью на файловую систему комплекта.
- `diag-perf` — CPU/потоки и доступные частоты во время игры.
- `diag-memory` и `diag-klog` — память и ограниченный журнал ядра.
- `diag-display` — показатели вывода IGUI и самого менеджера.
- `diag-input` — показатели ввода и интерактивный тест контроллеров.
- `diag-uart` — разовый пассивный снимок учётного состояния UART0 в Linux.

Каждый сборщик подключает общий `diag-cycle` для сегментов и экспорта.
Сборщики включаются автоматически составом сборки, не параметрами запуска.
Без диагностических features отчёты не собираются и не экспортируются.
Активных UART/GPIO-проб в iman нет.
[Сегменты, команды и ограничения](docs/diagnostics.md).

## Данные и ограничения

IPC, журналы и временные файлы RetroArch находятся в проверенном tmpfs,
без резервного перехода на диск. Постоянные снимки состояния — в `games/states/`,
SRAM/RTC — в `games/saves/`; имена привязаны к SHA-256 ROM.
Предпочтения IGUI сохраняются явными действиями пользователя.

Профили комплекта задают `autosave_interval=60`: RetroArch проверяет изменения
SRAM раз в минуту и сохраняет её при штатном выходе. Автосохранение снимков
состояния, конфигурации и истории отключено. Диагностическая сборка автоматически
экспортирует сегменты в `iman-reports/` после игр и при штатном выходе.

**Менеджер не переключает SD между RO/RW и не гарантирует устойчивость
к отключению питания.** Уведомление внутри игры не подтверждает синхронизацию SD.
[Постоянные данные и границы гарантий](docs/runtime.md#временные-и-постоянные-данные).

## Исходники и инструменты

- [`runtime`](src/runtime/mod.rs) — проверенные файлы, запуск ELF и RAM-ресурсы.
- [`session`](src/session/mod.rs) — жизненный цикл и обработка IPC-команд.
- [`emulation`](src/emulation/mod.rs) — настройки RetroArch, BIOS, переназначение управления и параметры ядер.
- [`diagnostics`](src/diagnostics/mod.rs) — сборщики и ограниченные отчёты.
- [`display`](src/display/mod.rs) — DRM/PC, владение дисплеем и заставки.
- [`input_test`](src/input_test/mod.rs) — тест контроллеров и кандидаты профилей.

[Статический предпросмотр заставки](tools/splash_preview.rs) — Cargo example
`splash_preview` с feature `drm`; выдаёт PPM в stdout без обращения к устройствам.
[Оконный предпросмотр](docs/runtime.md#предпросмотр-отсутствующего-igui-на-пк)
использует обычный менеджер с feature `pc`.

## Проверки

Из каталога `iman`:

```sh
cargo test --locked -- --test-threads=1
cargo test --locked --all-features -- --test-threads=1
cargo check --locked --no-default-features --all-targets
```

Для синтетических дочерних программ нужен `python3.12` в PATH.
Тесты проверяют версию и находят абсолютный путь интерпретатора;
привязки к `/usr/bin` нет.
Тестовые конфигурации и профиль контроллера синтетические и находятся в самом iman.
Проверки отсчётов используют подменяемые монотонные часы; процессы и локальный IPC
проверяются в изолированных временных каталогах. Тесты не требуют
реальной SD, NOR, DRM или геймпадов и не подтверждают работу на ARM-устройстве.
Для аппаратного запуска нужна отдельно собранная совместимая цепочка компонентов.

[GitHub Actions](.github/workflows/rust-package.yml) задаёт те же host-проверки
на Ubuntu 24.04 с Rust 1.85.0/stable и Python 3.12. Отдельная задача проверяет
компиляцию ARMv7 musl с `drm,rgb565,diagnostics`, без запуска тестов на устройстве.
Workflow реагирует на push, pull request и ручной запуск; автоматической публикации нет.
