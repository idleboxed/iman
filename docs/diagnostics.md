# Диагностика iman

Состав определяется Cargo [features](../README.md#features).
Пассивные сборщики включаются автоматически при старте; параметров запуска
для их запуска/экспорта нет. Без диагностических features отсутствуют
соответствующие чтения, отчёты и автоматический экспорт.
`diag-cycle` — общая инфраструктура сегментов, а не самостоятельный источник.

Сбор идёт в RAM с ограниченными объёмами. Недоступный источник или ошибка
не превращаются в успешный нулевой замер. Отказ отдельного наблюдения
не требует остановить GUI/игру. Активных UART/GPIO-проб и управления питанием нет.

## Источники и результаты

| Данные | Файлы сегмента | Реализация |
|---|---|---|
| Счётчики записи и контекст ФС | `observation.json`, `cycle-io.json` | [io](../src/diagnostics/io.rs), [io_context](../src/diagnostics/io_context.rs) |
| CPU/потоки игры и доступные частоты | `diag_perf.json` | [perf](../src/diagnostics/perf.rs) |
| Память | `diag_memory.json` | [memory](../src/diagnostics/memory.rs) |
| Ограниченный хвост журнала ядра и ранние USB-записи | `diag_klog.json` | [klog](../src/diagnostics/klog.rs) |
| Вывод GUI и собственный вывод iman | `diag_display.json` | [display](../src/diagnostics/display.rs) |
| Показатели ввода GUI | `diag_input.json` | [input](../src/diagnostics/input.rs) |
| Завершённый тест контроллеров | `diag_input_test.json`, `pads-proposal/` | [input_test](../src/input_test/mod.rs) |
| Разовый учётный UART0-снимок Linux | `diag_uart.json` | [uart](../src/diagnostics/uart.rs) |

Файлы присутствуют по составу сборки и полученным данным, не как обязательный
пустой набор. Форматы и бюджеты отдельных источников задаются их реализациями.
Обёртки различают часы сеанса и область измерения; последовательные чтения
не являются атомарным снимком устройства.

I/O-источник определяется по ФС удерживаемого корня комплекта, не фиксированному
имени SD. Недоступность не заменяется произвольным другим диском.
Запись раздела входит в запись целого диска: их итоги нельзя складывать.
Отсутствие текущих запросов не доказывает отсутствие несохранённых данных
в страничном кэше или завершение записи внутри контроллера носителя.

Данные IGUI поступают от зарегистрированного подключения GUI. Отсутствие GUI
не подтверждает исправность его ввода/вывода. Собственные этапы отрисовки iman
учитываются отдельно; CPU-отрисовка, передача кадров и переключения буферов KMS не равнозначны.
CPU/частоты игры не доказывают причину её FPS без дополнительных измерений.

UART-снимок выполняется один раз при первом `gui_diagnostics` за сеанс,
не при обычном запуске меню. Без такого этапа `samples=0` означает отсутствие
измерения. Нет MMIO, открытия tty или `/dev/mem`, переключения тактирования или функций выводов.
Учёт Linux не доказывает электрическую готовность порта.

## Сегменты и экспорт

После игры идут две секунды пассивного наблюдения, затем снимок сегмента,
экспорт и новый IGUI. При штатном завершении сохраняется последний сегмент.
Снимок не сбрасывает живые сборщики. После отказа IGUI доступен отдельный
диагностический этап перед экранным отсчётом; [порядок](runtime.md#экран-менеджера).

Сегменты публикуются в `ROOT/iman-reports/` через удерживаемый проверенный
корень. `report.json` имеет формат `IMAN-CYCLE-1`, метаданные и таблицу
размеров/SHA-256 файлов отчёта. Сегмент содержит ограниченный `launch.log`;
если была выбрана игра, также записывается `retroarch.log`. Для чтения предыдущих сегментов
не требуется завершающий `session.json`.

Один активный сегмент и один неизменяемый снимок передаются потоку экспорта
с ограниченным объёмом данных; неограниченной очереди нет. Корень, вложенные пути,
та же ФС и свободное место проверяются до публикации.
После первой ошибки записи или превышения бюджета новые попытки запрещаются
до конца сеанса, в том числе при его завершении. Наблюдение может продолжаться,
но пропущенные сегменты не копятся для фонового повторного сохранения.

Ограничения текущего экспортера:

- файл отчёта или манифест — до 64 КиБ каждый;
- весь комплект отчёта, включая манифест, — до 256 КиБ;
- `pads-proposal/` — до девяти файлов и 32 КиБ суммарно;
- за сеанс — до 256 сегментов и 16 МиБ;
- до записи должно оставаться минимум 8 МиБ свободного места;
- запуск потока экспорта не меняет часы или политику опроса сборщиков.

SHA подтверждают состав опубликованных файлов отчёта, не аппаратную истинность данных.
Экспорт — реальная автоматическая запись на носитель, не режим RO и не гарантия
сохранения последнего сегмента при аварии.
Реализация: [cycle](../src/diagnostics/cycle.rs), [export](../src/diagnostics/export.rs).

## Чтение через IPC

Сначала запросите `core.capabilities` у конкретного сеанса.
Обычный клиент не включает/выключает сборщики, не выбирает PID и не подменяет
пути источников. Доступны чтение статусов/отчётов и проверенные команды передачи показателей
зарегистрированного GUI.

```sh
iman ctl /путь/к/control.sock diag_cycle.status
iman ctl /путь/к/control.sock diag_memory.report
```

Эти команды требуют соответствующую сборку; путь сокета и семантика ответов —
в [описании IPC](runtime.md#управление-через-ipc).
`diag_cycle.status` сообщает последнее сохранение, число/объём сегментов,
удерживаемый неуспешный снимок и постоянную ошибку экспорта.
Состояние RAM-отчёта само по себе не подтверждает запись на SD.

## Тест контроллеров

При `diag-input` IGUI после десяти секунд бездействия готового каталога
предлагает тест с десятисекундным отсчётом. B отменяет приглашение
до следующего запуска IGUI. Передача управления завершает GUI;
тест начинается только после получения статуса завершения GUI через `waitpid` и возврата дисплея.

Десять секунд сбора откликов определяют до четырёх участников.
Перед каждым — четыре секунды подготовки с просьбой взять контроллер
и отпустить органы управления. Подготовительные события не отвечают
на первый из 25 шагов; каждый шаг имеет отдельные пять секунд.
После теста идут десять секунд пассивной диагностики, прощальный отсчёт
и существующий экспорт сегмента.

Завершённые шаги могут сформировать кандидаты JSON IGUI/CFG RetroArch
в `pads-proposal/`, с именами `VID-PID-<хеш имени>`.
`summary.json` объясняет пропуски. Рабочие профили не заменяются,
назначения кнопок и состояние оборудования не меняются.
Путь отчёта показывается на пять секунд только после синхронизации;
до экспорта данные находятся в RAM. `diag_input_test.report` читает
журнал, не выполняет запись и не подтверждает её завершение.

Без `diag-input` модель, геометрия, компонент чтения событий и журнал теста не компилируются.
Остающийся в IGUI таймер приглашения/IPC не означает наличие теста в менеджере.
Переиспользование кадра не устраняет память профилей и состояния evdev
и не является измерением RSS на конкретной плате.
