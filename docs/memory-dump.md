# Дамп памяти

Дополнительный модуль iman читает заданный участок физической памяти.
Он подключается при сборке через `diag-memdump`, отдельно от обычной
диагностики.

**Неверный адрес может вызвать зависание устройства даже при чтении без записи.**
До включения чтения проверьте назначение участка памяти и доступ к нему
на своей плате. Таймаут не гарантирует восстановления при зависании.

## Профиль

JSON-файлы лежат в `system/iman/memory-profiles/`, рядом с конфигурацией iman.
[Пример профиля](../memory-profiles/rk3032-dongle.json).

| Поле | Назначение |
|---|---|
| `schema` | Версия формата: `1`. |
| `description` | Краткое описание участка памяти. |
| `match.compatible` | Точный идентификатор платформы из списка DT `compatible`. |
| `read.enabled` | `false` — пропустить чтение; `true` — разрешить попытку. |
| `read.address` | Начальный физический адрес: шестнадцатеричная строка с префиксом `0x`. |
| `read.length` | Сколько байтов прочитать: от 1 до 16384. |
| `read.unit` | Размер одного обращения: 1, 2 или 4 байта. Адрес и длина должны быть кратны ему. |

Профиль выбирается автоматически по одному `compatible`. Модель, архитектура
и версия ядра попадают в отчёт, но на выбор не влияют. Совпадение профиля
не подтверждает правильность адреса. Нет подходящего профиля, их несколько
или JSON повреждён — чтение пропускается. Запасных адресов нет.
Предел 16 КиБ и ожидание 1 секунду заданы в коде, не в JSON.

## Когда читается память

Одна попытка — при обычном выходе из всего приложения, после остановки меню
и эмулятора. Выход из отдельной игры чтение не запускает.
При ошибке, отмене или изменении выбранного профиля попытка пропускается.
Автоматических повторов нет, в том числе при новом запуске iman с тем же
временным каталогом. Отметка попытки находится в RAM и исчезает при перезагрузке.

Перед чтением iman показывает `Memory dump: reading`. Если показать начало
не удалось, чтения не будет. Затем в статусной строке появляется результат:

- `Memory dump: skipped - ...` — пропуск с причиной;
- `Memory dump: failed - ...` — ошибка или неполное чтение;
- `Memory dump: captured ... bytes in RAM` — байты получены в оперативную память.

## Где результат

При финальном сохранении диагностики в `iman-reports/` добавляются:

- `diag_memdump.json` — результат, причина пропуска или ошибки, профиль и сведения об устройстве;
- `memory-dump.bin` — полученные байты; при неполном чтении только полученная часть.

**Получение байтов в RAM ещё не означает сохранения на SD.** Дождитесь
`Diagnostics synchronized.` — подтверждения синхронизации отчётов.
Экспорт пишет на SD; устойчивость к внезапному отключению питания не гарантируется.
